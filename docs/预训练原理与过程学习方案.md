# 用已完成的 MiniMind 实验学习预训练：8 次学习方案

这份方案的目标是：你能够自己解释、检查和复现“文本如何变成训练目标，模型如何预测，误差如何改变参数，最后怎样生成文本”。已经完成的 RTX 4090 预训练提供了真实案例；接下来主要在 Mac 上读代码、追踪一个样本、运行小实验。

## 第 2 次：追踪一个样本，理解标签移位

代码入口：`dataset/lm_dataset.py:40` 与 `model/model_minimind.py:250`。

先从 JSONL 读一条 `text`，观察它是否包含问答。然后读 `PretrainDataset.__getitem__`：正文最多 338 个 token，加 BOS/EOS 后最多 340；不足的部分补 PAD；标签复制输入，再将 PAD 改成 `-100`。

“输入等于标签”并没有让模型抄答案：模型内部拿第 `t` 个位置的输出与第 `t+1` 个位置的标签比较，而且因果注意力阻止它看到未来。

用符号先写一遍：

| 预测位置的输入 | 允许看到的前缀        | 要预测的目标           |
| ------- | -------------- | ---------------- |
| BOS     | BOS            | A                |
| A       | BOS, A         | B                |
| B       | BOS, A, B      | EOS              |
| EOS     | BOS, A, B, EOS | PAD，对应标签 -100，忽略 |

**动手**：在项目根目录激活 `.venv` 后，运行下面的练习。它把 `PretrainDataset.__getitem__` 的单样本处理单独展开，避免首先加载整个大数据集。

```bash
source .venv/bin/activate
python - <<'PY'
import json
import torch
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained('model', local_files_only=True)
with open('dataset/pretrain_t2t_mini.jsonl', encoding='utf-8') as f:
    print('真实样本开头:', json.loads(next(f))['text'][:160])

text = '春天到了，花开了。'
max_length = 32  # 教学练习缩短长度；正式实验是 340
body = tokenizer(text, add_special_tokens=False,
                 max_length=max_length - 2, truncation=True).input_ids
ids = [tokenizer.bos_token_id] + body + [tokenizer.eos_token_id]
x = torch.tensor(ids + [tokenizer.pad_token_id] * (max_length - len(ids)))
y = x.clone()
y[x == tokenizer.pad_token_id] = -100

print('input_ids:', x.tolist())
print('labels:', y.tolist())
print('预测位置数:', int((y[1:] != -100).sum()))
for i in range(max_length - 1):
    target = int(y[i + 1])
    print(i, repr(tokenizer.decode([int(x[i])])), '->',
          '忽略' if target == -100 else repr(tokenizer.decode([target])))
PY
```

**预期观察**：BOS 预测正文第一个 token；正文最后一个 token 预测 EOS；PAD 目标不参与 loss。token 与汉字不必一一对应，单枚 token 的独立 decode 也可能显示不完整字符，完整序列的解码更可靠。

**验收**：能解释为什么忽略 PAD，却保留 EOS；删除 EOS 会失去什么监督；把正文截断为 338 个 token 会丢掉什么信息。

**进阶观察**：训练代码没有传入 padding attention mask。因为这里使用右侧 padding 和因果注意力，前面的有效位置看不到后面的 PAD；PAD 位置的目标又被忽略。不要把这个结论直接套用到左侧 padding 或非因果模型。

## 第 3 次：理解一次前向，验证“看不到未来”

代码入口：`MiniMindModel.forward`、`MiniMindBlock.forward`、`Attention.forward`、`FeedForward.forward`。

阅读顺序采用“整体 → 一个 Block → 注意力”，先不钻进 MoE 和 RoPE 外推细节。各组件的基本作用是：embedding 把编号映射成可学习向量；注意力在允许的前文范围内组合信息；FFN 对每个位置的表示做变换；残差连接把变换前的表示加回来；RMSNorm 控制表示的尺度；RoPE 给 Q/K 引入位置信息。

本次训练的主要张量形状：

| 位置                 | 形状                 | 每个维度的意义      |
| ------------------ | ------------------ | ------------ |
| input_ids          | `[32, 340]`        | 批次、序列位置      |
| embedding/Block 输出 | `[32, 340, 768]`   | 每个位置的隐藏表示    |
| 投影并拆头后的 Q          | `[32, 340, 8, 96]` | 查询头、每头维度     |
| 投影并拆头后的 K/V        | `[32, 340, 4, 96]` | KV 头、每头维度    |
| FFN 中间结果           | `[32, 340, 2432]`  | 前馈层中间表示      |
| logits             | `[32, 340, 6400]`  | 每个位置对整个词表的分数 |

注意力内部还会转置维度，并把 4 个 KV 头重复到与 8 个 Q 头对应。logits 是分数，不是已经归一化的概率。

**动手**：使用第 5 次提供的极小模型。先算一个输入 `x` 的 logits，再复制成 `x2` 并修改第 5 个位置的 token（索引 4）。在 `eval()` 和 `torch.no_grad()` 中比较：索引 0–3 的 logits 应相同，索引 4 及之后可以改变。不要用重新初始化的另一模型做比较。

这个实验直接检查因果掩码：第 4 个位置之前的输出不能依赖第 5 个位置的内容。对照代码中的 `is_causal=True` 和显式上三角掩码，解释两个注意力计算分支。

**验收**：能画出一个 Block 的残差连接，说明 Q/K/V 的用途，解释为什么训练能同时计算多个位置而没有偷看答案。

## 第 4 次：从预测概率到交叉熵

代码入口：`MiniMindForCausalLM.forward` 的 250–258 行。

针对某个正确 token，若模型分配概率 `p`，该位置的损失是 `-ln(p)`。交叉熵把有效位置的损失平均起来；`-100` 位置被忽略。`F.cross_entropy` 接收 logits，并在内部处理对应的归一化计算。

例如：正确目标的概率从 0.1 提高到 0.5，损失从约 2.303 降到 0.693。它奖励的是对目标 token 分配更高概率，不是直接评判一整段答案的真假。

**动手一**：用纸笔计算 `p=0.1、0.5、0.9` 时的 loss。将目标 token 改成另一个 token，再解释损失会如何改变。

**动手二**：在第 5 次的小模型上，将返回的 `res.loss` 与下式比较，应一致：

```python
manual_loss = torch.nn.functional.cross_entropy(
    res.logits[:, :-1, :].reshape(-1, model.config.vocab_size),
    y[:, 1:].reshape(-1),
    ignore_index=-100,
)
print(res.loss.item(), manual_loss.item())
```

再比较“正确移位目标”和“未移位目标”的区别。两者数值差多少不是重点，重点是后一种已经改变了训练任务。

**结合证据**：Dense 模型的 `aux_loss=0`，因此日志中的 loss 与 logits_loss 相同。`ln(6400)≈8.764` 是均匀词表分布的参考交叉熵，真实随机模型不一定等于它；已有学习文档和曲线红线标注的 `8.46` 数值不正确。

困惑度可写成 `exp(loss)`。最后那个批次 `exp(1.636)≈5.13`，只是同一批次的指标变换，不能写成独立测试集困惑度，也不是“正确率”。

**验收**：能说明 loss 小为什么通常意味着预测更贴近训练文本，却不能保证生成的科学解释正确。

## 第 5 次：亲眼观察 backward 与参数更新

代码入口：`train_epoch` 的 C–E 注释区块，以及 `AdamW` 构造位置。

先掌握三个区别：前向产生预测和 loss；`backward()` 计算参数梯度；`optimizer.step()` 才真正更新参数。梯度表示在当前点附近，参数变化怎样影响 loss；它没有保证在每个新批次上 loss 都更小。

下面使用本项目相同模型实现、相同分词器，缩小到 hidden_size=64、2 层、序列长度 32。这是教学模型，词表仍为 6400；不加载自己的正式权重。

```bash
python - <<'PY'
import torch
from transformers import AutoTokenizer
from model.model_minimind import MiniMindConfig, MiniMindForCausalLM

torch.set_num_threads(4)
torch.manual_seed(42)
tokenizer = AutoTokenizer.from_pretrained('model', local_files_only=True)
config = MiniMindConfig(hidden_size=64, num_hidden_layers=2,
                      max_position_embeddings=64)
model = MiniMindForCausalLM(config)  # CPU，随机初始化的小模型
optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3)

body = tokenizer('春天到了，花开了。', add_special_tokens=False).input_ids[:30]
ids = [tokenizer.bos_token_id] + body + [tokenizer.eos_token_id]
x = torch.tensor([ids + [tokenizer.pad_token_id] * (32 - len(ids))])
y = x.clone()
y[x == tokenizer.pad_token_id] = -100

param = model.model.embed_tokens.weight
before = param.detach().clone()
res = model(x, labels=y)
print('logits shape:', tuple(res.logits.shape))
manual_loss = torch.nn.functional.cross_entropy(
    res.logits[:, :-1, :].reshape(-1, config.vocab_size),
    y[:, 1:].reshape(-1), ignore_index=-100)
print('模型 loss / 手工 loss:', res.loss.item(), manual_loss.item())
res.loss.backward()
print('backward 后参数是否相同:', torch.equal(before, param.detach()))
print('梯度范数:', param.grad.norm().item())
grad_norm = torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
print('裁剪前全局梯度范数:', float(grad_norm))
optimizer.step()
print('step 后参数最大变化:', (param.detach() - before).abs().max().item())
optimizer.zero_grad(set_to_none=True)

# 因果性实验：修改第 5 个位置，比较它之前的位置。
model.eval()
with torch.no_grad():
    x2 = x.clone()
    x2[0, 4] = (x2[0, 4] + 1) % config.vocab_size
    a, b = model(x).logits, model(x2).logits
    print('未来 token 改动对前 4 个位置的最大影响:',
          (a[:, :4] - b[:, :4]).abs().max().item())

# 在同一句上继续训练，观察模型记住它的过程。
model.train()
for step in range(60):
    loss = model(x, labels=y).loss
    loss.backward()
    torch.nn.utils.clip_grad_norm_(model.parameters(), 1.0)
    optimizer.step()
    optimizer.zero_grad(set_to_none=True)
    if step % 10 == 0 or step == 59:
        print('重复同一句的更新', step + 1, 'loss', round(loss.item(), 4))
PY
```

**预期观察**：backward 后参数不变但梯度非零；step 后参数改变；修改未来 token 不影响前面的 logits；重复训练同一句时 loss 明显下降。具体 loss 数值取决于环境，不要求逐位相同。

**下一步动手**：换一句未训练的句子测 loss，解释“记住这一句”和“泛化到其他文本”的区别。该实验主要证明优化过程可以记住训练样本；单个新句子仍不足以评估泛化。

**编写方案时的运行验证**：2026-10-12 在本机 `.venv` 的 CPU 上，两段完整练习均运行成功。第一段短句有 9 个有效预测目标；第二段模型 loss 与手工 loss 都是约 8.7825，backward 后参数未变，step 后参数最大变化约 0.001；改变未来 token 对前 4 个位置 logits 的影响为 0；重复同一句的末次记录 loss 约 1.5299。这些数值是教学练习记录，不是正式 4090 模型的新训练结果。

再回到正式脚本：每个小批次的 loss 除以 8 后 backward，通常积累 8 个小批次再更新一次。每次更新通常处理 256 条样本，但每条有效 token 数可能不同，不是 256 个 token。

本次每轮 `39695 = 4961×8 + 7`，最后 7 个小批次也会触发更新，所以每轮 4962 次，两轮 9924 次，与最终优化器 step 相符。最后一个批次还有 30 条样本。

**进阶观察**：正式脚本最后不足 8 个小批次时仍把 loss 除以 8；而各小批次交叉熵按自身有效 token 平均。因此不要笼统声称它与任意一个完整大 batch 的 token 平均损失“严格等效”。

**验收**：能逐行解释为什么先 unscale、再裁剪、再 step、最后清零；指出 bf16 下 CUDA GradScaler 被禁用，这些 scaler 调用相当于没有缩放。

## 第 6 次：把日志还原成训练过程

代码入口：`train_epoch` 的 B、F 注释区块；`trainer_utils.get_lr`。

选一条真实日志逐项解释：

```text
Epoch:[1/2](10000/39695), loss: 2.3506, logits_loss: 2.3506,
aux_loss: 0.0000, lr: 0.00048261, epoch_time: 38.0min
```


这条记录来自原始日志第 98 行。`epoch_time` 由代码估算的是**本轮剩余时间**，不是已训练时长。loss 是当前小批次的值，不是最近 100 步平均值；log_interval=100 只是记录频率。

**动手**：按第 1 轮与第 2 轮拆分日志，给横轴统一换算：`global_step=(epoch-1)×39695+step`。计算并解释下表：

手算起点、中点、终点，应分别得到 0.0005、0.000275、0.00005。调度按小批次执行；没有 warmup，实际第一个小批次的 lr 已接近而不是精确等于理论起点。

**验收**：能解释前期下降较快、后期下降较慢的现象，同时把“观察”与“原因猜测”分开。现在没有恒定学习率对照实验，不能把曲线下降完全归因于余弦调度。

## 第 7 次：理解训练工程和断点续训

代码入口：训练脚本主程序的第 3、5、6、8 个准备区块；`lm_checkpoint` 与 `SkipBatchSampler`。

这节把工程做法与学习目标连接起来：

- 混合精度：autocast 让适合的算子使用低精度；不代表所有计算、梯度和 AdamW 状态都减半。本次 CUDA 配置使用 bf16，文件保存权重使用 fp16，这两件事不同。
- 梯度裁剪：限制更新前的梯度范数；训练稳定不等于已经测量并证实裁剪实际触发。
- 随机种子与打乱：控制随机过程，每轮重新排列样本；跨设备、跨版本不保证完全相同。
- 检查点：不仅保存“学到了什么”，也保存“优化过程走到了哪里”。

**动手**：读取当前最终检查点与备份的旧检查点，打印 `epoch`、`step`、`world_size`、`wandb_id`、优化器中的 step 与 lr。使用 `torch.load(..., map_location='cpu', weights_only=True)`，只查看状态，不继续训练。

`lm_checkpoint` 通过临时文件与 `os.replace` 保存，避免最终文件处于写到一半的状态；`out/` 的直接保存语句没有同样的原子替换机制。保存格式里的模型权重是 fp16，也没有完整保存随机状态，因此此实现恢复的是训练状态与位置，并非逐位精确复现。

**证据核对**：`gpu_status.txt` 是训练结束后的快照，显示 GPU 利用率 0%、显存 1 MiB。它能确认设备型号，不能证明训练时持续利用率 95% 或显存 7020 MiB。学习文档里的这些性能数字当前缺少对应快照支持。

**验收**：不运行脚本也能预测：当前最终状态下用 `--from_resume 1 --epochs 2` 不会再处理批次；如果改成更多 epoch，还必须考虑学习率总长度改变，不应把它称为完全延续原调度。

## 第 8 次：从学会预测到生成文本，完成复盘

代码入口：`model/model_minimind.py:262` 的生成循环；`eval_llm.py:73` 的预训练输入分支。

训练时，所有前缀目标来自已知文本，可以并行计算各位置预测；生成时，未来 token 未知，只能使用最后位置的 logits 选出一枚 token，追加后继续。KV cache 缓存已计算的键和值，减少重复计算；它不是保存对话内容的外部知识库。

**动手一**：从根目录运行 `python eval_llm.py --weight pretrain --max_new_tokens 128`，使用三个固定开头：“春天到了”、“天空呈蓝色的原因是”、“一个计算斐波那契数的 Python 函数如下”。记录输入、输出、模型与生成参数。

**动手二**：为了做可重复的对照，用一个自己的短 Python 脚本直接调用 `model.generate(..., do_sample=False, max_new_tokens=64)`；加载正式权重时使用 `strict=True`。固定同样输入与权重，比较贪心生成和采样生成。现有 CLI 每次随机设置种子并且默认采样，直接重复 CLI 的差异不能当作模型参数变化。

如需比较随机模型、旧 Mac 检查点、最终云端权重，要使用相同架构、输入、分词器和生成设置。旧 Mac 与最终云端记录属于不同实验过程，不是完整连续的中间检查点序列；这种对照只能作为能力变化的教学观察。

**动手三**：阅读已有 8 组生成证据，给每组分别记录：语言连贯性、是否遵循要求、事实是否可靠、代码能否运行、是否重复、是否正常结束。不要把“句子流畅”直接评分为“知识正确”；输出被截断时，也要考虑生成长度上限。

结合实际数据解释：预训练语料包含问答文本，所以模型在 SFT 前也可能表现出问答风格；预训练目标本身并没有专门区分“用户问题”和“助手答案”的监督范围。

最后写一页复盘，回答：

1. 本次训练输入是什么，标签从哪里来？
2. 一个 token 从编号经过哪些变换，最后怎么得到 loss？
3. backward、梯度累积、AdamW 分别做了什么？

## 最终自测

合上文档，用 5–10 分钟口头讲清：文本 → 分词 → BOS/EOS/PAD → 因果 Transformer → logits → 移位交叉熵 → backward → 累积与裁剪 → AdamW → 日志与保存 → 自回归生成。

然后预测五个改动的结果：去掉因果掩码、把 PAD 标签改成 0、只 backward 不 step、每批次都清零累积梯度、只加载模型权重而不恢复优化器。能讲清原因，并能从代码和实验中验证，才说明你已经掌握预训练的基本原理和过程。
