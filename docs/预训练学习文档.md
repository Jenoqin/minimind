## 〇、预训练是什么？（总览）

**原理**：预训练（Pretraining）是让模型从海量无标注文本中学习"下一个词是什么"的过程。
形式化为：给定 token 序列 $x_1, x_2, ..., x_T$，最大化似然 $\prod_{t} P(x_{t+1} | x_1, ..., x_t)$，
训练时等价于最小化交叉熵损失（Causal Language Modeling）。模型一旦学会预测下一个词，
就内化了语言的统计规律、常识和世界知识，为后续指令微调（SFT）提供"地基"。

**本实验的流程图**：

```
原始文本(jsonl) --分词--> token序列 --补BOS/EOS/padding--> input_ids/labels
                                                            │
模型(8层Transformer) --预测--> logits --交叉熵(标签移位一位)--> loss
                                                            │
                          反向传播 + AdamW + 余弦学习率调度 <--┘
                                                            │
                              周期性保存权重(.pth) + 完整检查点(_resume.pth)
```

## 一、环境与随机种子初始化

**原理**：深度学习训练充满随机性（权重初始化、数据打乱、dropout）。固定随机种子（seed）
能让实验可复现：同样的代码+数据+种子 ⇒ 同样的训练轨迹。DDP 多卡时每个 rank 用
`seed + rank`，保证各卡数据增强/初始化不同但不失确定性。

**代码位置**：`train_pretrain.py:101-104` → `trainer_utils.py:56-63`（`setup_seed`）

**做了什么**：设置 Python `random` / numpy / torch / CUDA 四级随机源；同时关闭 cudnn 的
非确定性算法（`benchmark=False`）。

**预期结果**：两次相同配置的训练，loss 曲线应完全一致。

## 二、模型配置与断点检测

**原理**：训练前先根据超参数构建模型配置对象（`MiniMindConfig`），并检查是否存在
可续训的检查点。这一步决定模型"长什么样"以及"从哪继续"。

**代码位置**：`train_pretrain.py:106-109`；`model/model_minimind.py:10-45`

**本实验的模型配置**（命令行参数决定）：

| 配置项 | 值 | 含义 |
|--------|-----|------|
| hidden_size | 768 | 隐藏层维度 |
| num_hidden_layers | 8 | Transformer 层数 |
| vocab_size | 6400 | 词表大小（BPE 训练得到） |
| num_attention_heads / num_key_value_heads | 8 / 4 | GQA：8 个查询头共享 4 个 KV 头，省显存 |
| max_seq_len | 340 | 训练最大序列长度 |
| intermediate_size | ceil(768×π/64)×64 = 384 | FFN 中间维度（SwiGLU） |
| tie_word_embeddings | True | 输入 embedding 与输出 lm_head 共享权重 |
| rope_theta | 1e6 | RoPE 位置编码的基频 |

**架构要点**（`model_minimind.py`）：
- **RMSNorm**（`:50`）：比 LayerNorm 更简化的归一化，只做均方根缩放
- **RoPE 旋转位置编码**（`:62-89`）：把位置信息编码进 Q/K 向量，支持相对位置泛化
- **GQA 注意力**（`:91`）：分组查询注意力，KV 头数减半以降低 KV cache
- **SwiGLU 前馈网络**（`:136`）：`W2(SiLU(W1x) ⊙ W3x)`，LLaMA/Qwen 同款
- **因果 LM 损失**（`:250-258`）：`logits[..., :-1, :]` 对 `labels[..., 1:]` 做交叉熵——
  **标签移位一位**是自回归训练的核心：用前 t 个 token 预测第 t+1 个

**预期结果**：日志打印 `Model Params: 63.91M`，从头训练时（`from_weight='none'`）
不加载任何权重。

**实际结果**：✅ 第一次试跑日志确认
```
Model Params: 63.91M
Trainable Params: 63.912M
```
证据：`logs/pretrain.log` 开头部分。

## 三、混合精度训练（AMP）

**原理**：用低精度（bf16/fp16）做前向和反向计算，可翻倍吞吐、减半显存；
但优化器状态、master 权重仍保持 fp32 保证数值稳定。bfloat16 动态范围与 fp32 相同，
**不需要** loss scaling（GradScaler 自动禁用）；float16 范围小，必须缩放 loss 防下溢。

**代码位置**：`train_pretrain.py:111-114, 129`

```python
dtype = torch.bfloat16 if args.dtype == "bfloat16" else torch.float16
autocast_ctx = torch.cuda.amp.autocast(dtype=dtype)   # 前向时自动转低精度
scaler = torch.cuda.amp.GradScaler(enabled=(args.dtype == 'float16'))  # bf16下自动失效
```

**预期结果**：本实验用 bf16 → `scaler` 实际不生效（`enabled=False`），
GradScaler 调用变成无操作；显存占用显著低于 fp32（理论上省约一半）。

**实际结果**：✅ 训练稳定运行中，bf16 下显存占用 **7020 MiB / 24564 MiB**（约 29%），
GPU 利用率 95%+。63.91M 参数若纯 fp32 训练，仅参数+梯度+AdamW 状态就需约 3GB，
且前向激活会大得多——bf16 混合精度让小模型训练极轻量。
证据：`docs/evidence/gpu_status.txt`（nvidia-smi 快照）。

## 五、模型、数据、优化器的构建

### 5.1 Tokenizer 与模型初始化

**原理**：`init_model`（`trainer_utils.py:121-133`）加载 `model/` 目录下的 BPE 分词器
（`tokenizer.json`，词表 6400），用配置从零实例化 `MiniMindForCausalLM`（Kaiming 初始化），
并打印参数量。

**预期结果**：`Model Params: 63.91M`（其中 embedding 占 6400×768≈4.9M，且与 lm_head 共享）。

### 5.2 数据集处理（重点）

**原理**：`PretrainDataset`（`dataset/lm_dataset.py:40-58`）完成"文本 → 模型输入"的转换：

```python
tokens = tokenizer(text, max_length=max_length-2, truncation=True).input_ids  # 截断到338
tokens = [BOS] + tokens + [EOS]                    # 加首尾特殊标记
input_ids = tokens + [PAD] * (max_length - len)    # 补齐到340
labels = input_ids.clone()
labels[input_ids == PAD] = -100                    # padding 处不计算损失
```

三个关键设计：
1. **BOS/EOS**：告诉模型"一句话从这里开始/结束"，学会有边界地生成
2. **padding + `-100`**：PyTorch 交叉熵默认忽略 `-100` 的位置，避免模型学习"输出 padding"
3. **截断**：超长文本直接截断（预训练常见做法，不滑窗，简单高效）

**数据本身**：`pretrain_t2t_mini.jsonl`，127 万条中文语料（预清洗/去重后的通用文本+对话文本）。

**预期结果**：数据集加载日志打印 `1270238 examples`。

**实际结果**：✅ 试跑日志确认（`Generating train split ... 1270238 examples`），见证据 E-05。

### 5.3 优化器

**原理**：`AdamW`（`train_pretrain.py:130`）——在 Adam（自适应学习率 + 动量）基础上
解耦 L2 正则（weight decay）。初始 lr=5e-4，具体值每个 step 由学习率调度函数覆盖。

**预期结果**：`optimizer.param_groups[0]['lr']` 随训练从 5e-4 余弦下降。

## 六、学习率调度（余弦退火 + 最小值兜底）

**原理**：`get_lr`（`trainer_utils.py:42-43`）：

```python
return lr * (0.1 + 0.45 * (1 + cos(pi * step / total_steps)))
```

- `cos` 项从 1 → -1，所以整体系数从 **1.0 余弦衰减到 0.1**
- 训练初期大步长快速下降 loss；后期小步长精细收敛，避免在最优点附近震荡
- 最低保留 10% lr 防止后期"走不动"

**预期结果**：SwanLab 的 learning_rate 曲线呈余弦形状（注意：不是从 0 升温的 warmup 版本）。

**实际结果**：✅ 与公式推导完全一致。日志实测：step 1100 时 lr=4.9979e-4，step 8100 时
lr=4.8854e-4，从初始 5e-4 平滑余弦衰减中（总步数 = 2×39695，当前仍在曲线前段）。
证据：`docs/evidence/loss_lr_curve.png` 右图（从训练日志解析绘制）。

## 七、训练循环（核心中的核心）

**代码位置**：`train_pretrain.py:24-71`（`train_epoch`）

逐步拆解每一次迭代：

```
for step, (input_ids, labels) in enumerate(loader):
 ① 数据搬到 GPU                    :27-28
 ② 计算当前 step 学习率并覆盖       :29-31
 ③ autocast 上下文中前向，得 loss   :33-36   loss = (res.loss + res.aux_loss) / accumulation_steps
 ④ scaler.scale(loss).backward()    :38      反向传播，累积梯度
 ⑤ 每 8 步（accumulation_steps）：   :40-47
     - unscale_：把缩放后的梯度还原
     - clip_grad_norm_：梯度裁剪（阈值1.0），防梯度爆炸
     - scaler.step(optimizer)：真正更新参数
     - scaler.update()：动态调整缩放系数（fp16）
     - zero_grad：清零梯度（下一轮重新累积）
 ⑥ 每 100 步：打日志 + 上报 SwanLab :49-57
 ⑦ 每 1000 步 / epoch 末：保存权重 :59-69
```

**三个必懂的设计**：

1. **梯度累积**（`accumulation_steps=8`）：显存放不下 256 的"物理 batch"，
   就分 8 次喂 32，把梯度累加起来再更新——**等效 batch_size = 32×8 = 256**，
   既不爆显存又不减小 batch。
2. **梯度裁剪**：RNN/Transformer 训练常见 trick，全局梯度范数超过 1.0 就按比例缩小，
   防止偶发的 loss 尖刺把训练"炸飞"。
3. **loss 除 8 再 backward**：让 8 次小 loss 的梯度之和 = 大 batch 的平均 loss 的梯度
   （数学上严格等效于 mean reduction）。

**预期结果**：
- 初始 loss ≈ ln(vocab_size) = ln(6400) ≈ **8.46**（随机初始化模型的理论起点）
- loss 随训练稳定下降，epoch 1 结束约 3~4，epoch 2 结束更低
- 每步耗时稳定，无 loss NaN / 爆炸

**实际结果**：✅ **训练已完成**（2 epoch 共 79390 步，784 个日志点），全程符合预期：

| 全局 step | loss | 说明 |
|-----------|------|------|
| 0（起点） | ≈8.46（理论值） | 随机初始化，等价于均匀猜测 6400 个词 |
| 1100 | 4.91 | 快速下降期 |
| 10000 | ~2.5 | epoch 1 中段 |
| 39695（epoch 1 末） | ~2.0 | 见曲线下平台期 |
| 50000 | ~2.0 | epoch 2 起步略低于 epoch 1 终点 ✅ |
| 79390（最终） | **1.636** | lr 同时衰减到 5e-5（=初始值×0.1，与公式精确吻合）|

- loss 单调趋势下降、无 NaN、无爆炸尖刺 → 梯度累积与梯度裁剪工作正常
- 最终 loss 优于"3~4"的预期，原因是数据质量高 + 6400 小词表
- 实际耗时约 **100 分钟**（2 epoch，单卡 4090）

## 九、Epoch 循环与数据打乱

**原理**：`train_pretrain.py:149-159`
- 每个 epoch 用 `torch.randperm` 重新打乱样本顺序，模型不会按固定顺序"背题"
- `SkipBatchSampler`：续训时跳过本 epoch 已训练的前 N 个 batch，不重训、不漏训
- 数据集共 127 万条 ÷ batch 32 ≈ **39700 batch/epoch**，2 epoch 共约 79400 步

**预期结果**：日志出现 `Epoch:[1/2]` → `Epoch:[2/2]`，第二 epoch 的 loss 起点低于第一 epoch 终点。

**实际结果**：✅ 日志确认每 epoch **39695 个 micro-batch**（127 万条 ÷ 32 = 39695，
与理论计算一致）。第二 epoch 的 loss 起点（~2.0）低于第一 epoch 终点（~2.1），
符合"再次遍历打乱后的数据会进一步下降"的预期。
